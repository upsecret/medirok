# 성능 감사 — 2026-08-14

"페이지 전환이 느리고 이미지도 느리다"는 신고에서 출발했다. 체감은 사실이었고,
원인은 **세 개의 독립된 구조적 문제**였다. 셋 다 코드 품질 문제가 아니라
**설정 한 줄이 빠져서 전체가 느린 경로로 흐르는** 형태였고, 그래서 지금까지
아무에게도 보이지 않았다.

측정은 전부 `curl -w`(HTTP/2, `--compressed`) 3회 반복 · 캐시 버스팅 5회 병행.
Edge PoP `kix1`(오사카). 네트워크 설정 비용 ~70ms는 전 구간 동일하다.

## 원인 ① 컴퓨트와 DB가 지구 반대편

`vercel.json`이 없어 함수 리전이 기본값 `iad1`(버지니아)였다. Neon DB는
`ap-southeast-1`(싱가포르)다. **모든 쿼리가 대륙을 건넜다.**

근거: 쿼리 2개 페이지 0.74s → 쿼리 7개 페이지 1.86s. **쿼리당 약 224ms**로,
iad1↔싱가포르 왕복 지연대와 일치한다.

조치: `vercel.json`에 `{"regions": ["sin1"]}`. 캐시 미스 렌더는 쿼리를 연달아
하므로 컴퓨트를 DB 옆에 두는 편이 사용자 옆(`icn1`)에 두는 것보다 낫다. 캐시
히트는 어차피 엣지(`kix1`)에서 나간다.

**이 한 줄이 3~6배를 만들었다.** 다른 모든 조치의 비용을 곱셈으로 줄인다.

## 원인 ② 콘텐츠 페이지가 하나도 캐시되지 않음

`.next/prerender-manifest.json`의 `dynamicRoutes`가 **빈 배열**이었다.
운영 실측으로도 12개 중 10개가 `cache-control: private, no-store` + `MISS`.

원인이 두 갈래였다.

**(a) `force-dynamic` 명시 8곳.** 그중 **4곳은 `generateStaticParams`까지
갖춰놓고 `force-dynamic`이 그것을 무력화**하고 있었다.

**(b) `revalidate = 1800`인데 `generateStaticParams`가 없는 4곳.**
동적 세그먼트에 `generateStaticParams`가 없으면 Next가 prerender 매니페스트에
항목을 만들지 않아 **`revalidate` 선언이 통째로 무시된다.** 이 4곳은 ISR을
켰다고 믿고 있었지만 실제로는 한 번도 동작한 적이 없다.

조치:
- 8곳의 `force-dynamic` → `revalidate`
- 4곳에 `generateStaticParams` 신설
- 프리렌더 대상 경로를 `src/lib/route-params.ts` 한 곳으로 모으고 **sitemap이
  같은 계산을 쓰게** 했다. 갈라지면 "sitemap엔 있는데 프리렌더는 안 되는"
  조합이 조용히 생긴다 — 그게 정확히 (b)의 상태였다
- `/hospitals`는 서버 `searchParams` 의존을 `HospitalFinder`의
  `useSearchParams`로 옮겨 정적화

빌드 라우트 표 기준 콘텐츠 라우트 14개 중 **12개가 `○`/`●`로 전환**됐다.

### 즉시성은 어떻게 지키나

이 프로젝트는 드래프트 없이 운영 DB에 직접 시드하고 "시드는 즉시 라이브"를
전제로 굴러왔다. `force-dynamic`은 그 대가였다.

`POST /revalidate`(`REVALIDATE_SECRET` 헤더) 엔드포인트를 만들고 **모든
`seed:*` npm 스크립트 뒤에 `npm run revalidate`를 체이닝**했다.
`revalidatePath("/", "layout")` + `revalidatePath("/sitemap.xml")`.
sitemap은 레이아웃 트리 밖의 라우트 핸들러라 별도 호출이 필요하다.

> 이걸 빠뜨리면 발행 후 최대 `revalidate`초 동안 옛 화면이 **조용히** 나간다.

## 원인 ③ 모든 이미지가 서버리스 함수를 경유

Payload가 내보내는 미디어 `url`은 Blob을 쓸 때조차 **항상**
`/api/media/file/<filename>`이었다. 라이브러리 코드를 직접 읽어 확인한 연쇄:

1. `plugin-cloud-storage/dist/plugin.js:73` — `disablePayloadAccessControl`이
   falsy면 `adapter.staticHandler`가 등록되어 프록시 라우트가 살아난다
2. `hooks/afterRead.js:6-13` — 그 플래그가 없으면 Blob 절대 URL 생성기
   (`adapter.generateURL`)가 **호출되지 않는다**
3. `storage-vercel-blob/dist/index.js:94` — 그런데 **래퍼가
   `cloudStoragePlugin`에 세 개 옵션(`alwaysInsertFields`·`collections`·
   `useCompositePrefixes`)만 전달한다.** `disablePayloadAccessControl`은
   타입에도 없고 런타임에도 도달하지 못한다
4. `payload/dist/uploads/generateFilePathOrURL.js:11-14` — 외부 URL 조기 반환
   조건이 `!url.startsWith(serverURL || "")`인데, `serverURL`이 없으면 `""`이고
   **모든 문자열은 `.startsWith("")`가 true**다. 조기 반환이 구조적으로 발동하지
   못한다

그 프록시 경로 1회 요청 = 서버리스 부팅 → media 4-way OR 쿼리 → Blob HEAD →
Blob GET. 마지막 GET에 `Cache-Control: no-store`가 박혀 있어
(`getFile.js:65`) 업로드 시 지정한 1년 캐시가 무력화된다.

조치: `createVercelBlobAdapter`가 공개 export가 아니라 플러그인을 우회하면
내부 경로에 의존하게 된다. 대신 **미디어 URL의 유일한 진입점인
`mapMediaDoc`에서 CDN 주소로 바꾼다**(`publicMediaUrl`,
`src/lib/payload-mappers.ts`). 토큰이 없는 환경(e2e·로컬)은 로컬 디스크
폴백이라 상대 경로를 그대로 둔다.

부수: `next.config.ts`의 `deviceSizes`를 8단계 → 4단계로 좁혔다. 원본이
card 768px / feature 1280px라 상위 후보들이 **같은 결과물을 서로 다른 캐시 키로**
만들고 있었다(실측 `w=828`·`w=1920`·`w=3840`이 전부 8,968 bytes로 동일).
`formats`에 avif 추가, `minimumCacheTTL` 1년.

> `next.config.ts`와 `src/lib/site.ts`의 주석이 **둘 다 사실과 반대로** 적혀
> 있었다("토큰 미설정 시에만 프록시", "Blob은 이미 절대 URL"). 이 오해 때문에
> 지금까지 문제로 인지되지 않았다. `**.public.blob.vercel-storage.com`
> remotePattern은 한 번도 매칭된 적이 없었다.

## 그 밖의 조치

- **쿼리 왕복 절반** — 7개 `find` 전부에 `pagination: false`. Payload는
  `pagination !== false`일 때 `SELECT` 외에 `COUNT(DISTINCT)`를 추가로 날린다
  (`@payloadcms/drizzle/dist/find/findMany.js:125`). 전량 조회라 총계를 안 쓴다
- **중복 쿼리 제거** — `getHospitalsByDeptAndRegion`·`getMagazineBySlug`를
  `cache()`로 감쌌다. `generateMetadata`와 페이지 본문이 각각 호출해 동일
  쿼리가 요청당 2번 돌고 있었다
- **커넥션 풀** — `max: 5`. 서버리스는 인스턴스가 옆으로 늘어나므로 인스턴스마다
  기본값 10을 잡으면 Neon pooler 한도에 먼저 부딪힌다
- **LCP** — 목록 최상단 카드에 `priority`. `Thumbnail`의 기본값이 lazy인데
  목록에서 한 번도 덮어써지지 않아 LCP 이미지가 전부 lazy였다
- **로고 `sizes`** — `HospitalBrandCover`의 로고 `<Image>`에 `sizes`가 없어
  48px로 그릴 이미지를 원본 폭 기준으로 요청했다
- **번들** — 역 목록(56KB 데이터, 라우트 청크 72.8KB)이 `/hospitals` 첫 로드에
  무조건 실렸다. "역주변" 탭을 열 때 받도록 `next/dynamic` 전환
- **폰트** — 외부 오리진 2곳(jsdelivr·Google Fonts) 렌더 블로킹에 `preconnect`

## 하지 않은 것 (사유)

- **`select` 컬럼 프루닝** — 전 컬렉션이 2~49행이고 페이지가 이제 캐시되므로
  이득이 사실상 없다. 반면 화이트리스트에서 매퍼가 읽는 필드를 하나라도
  빠뜨리면 **화면이 조용히 빈다.** 컬렉션이 커지면 재검토한다
- **`Media.imageSizes` 정리** — `thumbnail`(400×300)은 `payload-mappers.ts`에서
  매핑조차 안 되는 죽은 파생본이고, `feature`(1280×720)는 시드 원본과 치수가
  같아 바이트 중복이다. 다만 변경하면 **스키마 변경 + 기존 미디어 전량 재처리**가
  따라온다. 런타임 지연 기여도가 낮아 별건으로 남긴다
- **`formatOptions`로 파생본 WebP화** — 같은 이유(전량 재처리). 최종 출력은
  Next가 이미 AVIF로 바꿔주므로 브라우저 다운로드 크기는 방어되고 있다
- **`next/font` self-host** — preconnect까지만. 폰트 교체는 시각 회귀 범위가 넓다

## 회귀 가드

`e2e/perf.spec.ts` 3건. 셋 다 "눈에 안 띄는" 종류의 회귀라 테스트로 고정했다.

1. 콘텐츠 라우트에 `force-dynamic`이 다시 붙지 않는다
2. 동적 세그먼트 라우트에 `generateStaticParams`가 있다 (위 2곳은 사유와 함께 제외)
3. 이미지가 `/api/media/file` 프록시를 직접 가리키지 않는다 (Blob 사용 환경에서만)

재측정 스크립트는 이 문서의 표를 만든 것과 같은 방법을 쓴다 —
`curl -w "%{time_starttransfer}"` 3회 + `x-vercel-cache`·`x-vercel-id` 확인.
