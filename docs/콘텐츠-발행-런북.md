# 콘텐츠 발행 런북

`medirok_콘텐츠_발행팩.md` §6 체크리스트를 실제 실행 절차로 옮긴 문서. 신규 매거진 발행 시 이 순서를 따른다.

> 병원 블로그(`/blog`, 네이버 이식) 발행은 절차가 대부분 같고 **다른 점만** §9에 정리했다.

## 0. 전제

- 콘텐츠는 **DB에만** 존재한다. MDX/파일 없음. 발행 경로는 시드 스크립트(`scripts/seed-magazine-*.ts`) 또는 `/admin`.
- **드래프트 상태가 없다.** 시드 실행 = 즉시 라이브.
- `.env.local`은 **운영 Neon DB**를 가리킨다. 시드는 반드시 `getSeedPayload()`(`scripts/seed-payload.ts`)를 경유해 `PAYLOAD_DB_PUSH=false`로 스키마 push를 차단할 것.
- 매거진 상세·사이트맵은 `force-dynamic`이라 **시드 즉시 반영**된다(배포 불필요).

## 1. 원고 작성

1. `docs/매거진-*.md`에 원고·필드·검증 근거를 기록
2. **사실 원칙**: 병원 관련 서술은 `scripts/seed-yeon.ts`·`scripts/seed-dod.ts`의 검증분만 사용. 미확인 수치·밀집도·비율·최상급 표현은 쓰지 않는다.
3. 가격은 `prices: []`인 병원이면 `priceTable` 미사용 (추정가 미조작).

### 마크다운 주의 — 볼드가 안 닫히는 경우

닫는 `**` **앞이 구두점이고 뒤가 한글/영문**이면 CommonMark의 right-flanking 조건을 만족하지 못해 강조가 닫히지 않고 `**`가 원문 그대로 노출된다.

```
✗ **... 지정하는 '첨단재생의료실시기관'**에서만 가능합니다   ← 닫는 ** 앞이 ' , 뒤가 한글
✓ **... 지정하는 첨단재생의료실시기관**에서만 가능합니다
✓ **목업(Mock-up)** — 임시 재료로 ...                      ← 닫는 ** 뒤가 공백이면 OK
```

2026-07 W3 발행 때 원고 03에서 실제로 발생했고 운영 스모크 e2e가 잡았다.

### 링크 정책

본문 내부 링크는 **루트 상대 경로**로 쓴다.

```
✓ [예온치과병원](/hospital/예온치과병원)
✗ [예온치과병원](https://www.medirok.com/hospital/예온치과병원)
```

`src/components/Markdown.tsx`가 자사 호스트를 내부로 판정하도록 고쳐져 절대 URL도 이제는 follow 처리되지만, 상대 경로가 정공법이다. 병원 공식 사이트 등 진짜 외부 링크는 절대 URL로 두면 `nofollow`+`_blank`가 붙는다.

## 2. 시드 스크립트

`scripts/seed-magazine-geomdan.ts`를 템플릿으로 복사 → `package.json`에 `seed:magazine-<name>` 추가.

`upsertWithRefs`가 slug를 FK로 변환하므로 참조 대상(병원·진료과·지역)이 **먼저 존재해야** 한다. 없으면 에러가 아니라 `⚠ 매칭 실패` 경고만 나고 관계가 빈다 — **로그를 반드시 눈으로 확인**.

- 진료과 slug는 영문(`dental`, `dermatology`), 지역 slug는 한국어(`서구`, `강남구`, `인천`)
- `type`은 기존 enum만(`article|qna|regional|interview|case`). 새 값은 Payload 마이그레이션 필요
- `category`는 자유 텍스트 — `醫錄 인증`처럼 enum에 없는 표기는 여기에 넣는다

## 6. 색인 요청

```bash
npm run indexnow -- --dry-run /magazine/<slug>     # 페이로드·URL 상태만 확인
npm run indexnow -- /magazine/<slug>               # 실제 제출 (202 정상)
```

- 키 파일: `public/0bdf2a333d270c77d8a632f9455079de.txt` → `https://www.medirok.com/<key>.txt`가 200이어야 한다. 스크립트가 전송 전 자동 확인한다.
- IndexNow = Bing 계열. **ChatGPT 검색이 Bing 인덱스를 쓰므로 인용의 전제 조건.**
- **Google Search Console은 수동** (API 자격증명 없음): URL 검사 → 색인 생성 요청. Gemini 대응.

## 7. 전체 매거진 원문 노출 스캔

```bash
curl -s https://www.medirok.com/sitemap.xml | grep -oE '<loc>[^<]*/magazine/[a-z0-9가-힣-]+</loc>' | sed 's/<[^>]*>//g' | while read -r u; do
  out=$(curl -s "$u" | python3 -c "
import sys,re,html
h=sys.stdin.read(); m=re.search(r'<article.*?</article>',h,re.S)
if not m: print('NO-ARTICLE'); raise SystemExit
t=html.unescape(re.sub(r'<[^>]+>',' ',m.group(0))); bad=[]
for pat,name in [(r'^#{1,4}\s','heading'),(r'\*\*[^*]+\*\*','bold'),(r'^\|.+\|.+\|\$','table'),(r'\[[^\]]+\]\(https?://','link')]:
    if re.search(pat,t,re.M): bad.append(name)
print(','.join(bad) if bad else 'ok')")
  printf "%-6s %s\n" "$out" "${u##*/magazine/}"
done
```

## 9. 병원 블로그 (`/blog` — 병원 공식 콘텐츠 재구성, enterprise)

병원이 직접 공개한 글(**네이버 블로그 포스팅** 또는 **병원 웹사이트 칼럼**)을 **주제별로 재구성**해 싣는 기능. 원본은 그대로 두고 메디록이 원출처를 명시한다. 매거진과 컬렉션·라우트가 분리돼 있다. 채널(네이버/웹사이트)은 원출처 URL 호스트로 판정해 화면 문구·JSON-LD를 가른다(`src/lib/blog-source.ts`, 2026-09-16 일반화).

> **재게시 동의가 문서로 남아 있지 않은 병원의 글은 새로 발행하지 않는다** — `docs/content-sources.md` §0. 원출처 사이트가 무단 복제를 명시적으로 금하는 경우가 있다.

> **발행·수정 후에는 `docs/content-sources.md`(출처 대장)를 반드시 갱신한다.** 글 추가·삭제, 참조 원문 변경, 본문 실질 수정, 썸네일·의원 로고·커버 교체, 저자 변경이 대상이다. DB는 "지금 상태"만 보여 주므로 **무엇이 언제 왜 바뀌었는지는 그 문서에만 남는다** — 병원이 원문을 내렸을 때·이미지 사용 범위를 확인할 때 그걸 먼저 본다.

### 9-1. 매거진과 다른 점만

| 항목 | 매거진 | 병원 블로그 |
|---|---|---|
| 컬렉션 | `magazines` | `blog-posts` |
| URL | `/magazine/<slug>` | `/blog/<병원slug>/<slug>` (3레벨) |
| 병원 관계 | `linkedHospitals` (hasMany, 선택) | `hospital` (단수, **필수**) — URL 1단계 |
| 원출처 | 없음 | `sourceBlogName`·`sourceBlogUrl`·`sourcePosts[]` **필수** |
| JSON-LD | `Article` | `BlogPosting` + `isBasedOn`/`citation` |
| 시드 | `seed:magazine-*` | `seed:blog-posts` (3편 일괄) |
| 원고 문서 | `docs/매거진-*.md` | `docs/블로그-*.md` |

### 9-2. 집필 원칙 (§1에 더해)

- **1:1 복제 금지.** 한 편은 원문 여러 편의 종합이고, 근거가 된 원문은 `sourcePosts`에 **전부** 기재한다. 누락하면 출처 없이 옮긴 것이 된다.
- 의료 서술은 병원이 직접 작성·공개한 원문의 것을 유지한다(원출처가 병원이므로). 단 **최상급·타 의료기관 대비 우위 주장은 옮기지 않는다** — §1의 사실 원칙 그대로.
- 병원 시설·진료시간·주소는 원문이 아니라 `seed-yeon.ts`/`seed-dod.ts` 검증분을 쓴다. 원문끼리 표기가 엇갈리는 경우가 있다(예온 원문의 "검단구" vs "서구").
- `authorDoctor`는 **원장 1인칭 글일 때만** 설정한다. JSON-LD `author`가 Person↔Organization으로 갈리고 저자 프로필 박스 노출도 달라진다.
- 이미지는 쓰지 않는다(v1). 네이버 이미지(`pstatic.net`)는 Referer 차단으로 핫링크가 깨지고, 자체 호스팅 파이프라인이 없다.

#### 어투 — 병원마다 다르게 쓴다 (2026-08-03 신설)

파일럿 3편을 전부 같은 무색 3인칭 설명체로 썼다가 재작성했다. 이 항목이 없어서 벌어진 일이다.

**본문은 그 병원 블로그의 목소리를 따른다. 3편이 서로 다른 문체를 갖는 것은 정상이다.**

| 원문 성격 | 본문 어투 | 근거 |
|---|---|---|
| **원장 1인칭 명의** (`authorDoctor` 설정) | 1인칭 + 원문의 구어체 어미 | JSON-LD `author`가 Person으로 나가고 저자 박스가 뜬다. 본문이 3인칭이면 **저자 선언과 문체가 어긋난다** |
| **병원 명의** (`authorDoctor` 없음) | "-습니다" 서면체. 원문 술자의 판단·결정은 **인용 블록**으로 | `author`가 Organization이라 본문 1인칭은 화자 없는 1인칭이 된다. 인용은 출처 명시 원칙과도 맞는다 |

**어투 반영은 원문 복제가 아니다.** 병원 블로그는 대행 작성이 섞여 문체가 편마다 다르고 품질도 고르지 않다. 실제로 예온 원문 3편 중 하나는 "이어집니다/요구됩니다"가 43회 반복되는 스핀 텍스트였고 하나는 이모지 CTA 광고문이었다. **가져올 것과 버릴 것을 나눈다.**

- 가져온다 — 질문형/번호 소제목, 술자 시점 케이스 서술, 반복되는 시그니처 수사, 하단 Q&A 구조
- 버린다 — 스핀 반복, 이모지 불릿, CTA·권유 문구, 키워드 스터핑, 인사말/맺음말 상투구, 하단 주소 블록

**반복되는 시그니처 수사는 blockquote로 살린다.** 디오디 원문의 "여기서 구분해야 할 게 있어요 → A와 B는 다른 개념" 프레임이 그 예다(4편에 13회). 대비 명제가 인용 단위로 떨어져 AEO에도 유리하다.

**`shortAnswer`·`metaDescription`·FAQ는 메디록 중립체를 유지한다.** 답변 추출 단위라 화자색이 없는 편이 낫고, 본문만 병원 목소리를 갖는 대비가 매체 성격을 분명히 한다.

**구어체를 넣을 때의 의료광고 가드** — 1인칭 구어체는 원리 설명과 판단 근거에만 쓴다. 시술 권유("제가 해드립니다"), 효과 보증, CTA는 금지다. 특정 치료 경과를 자세히 쓸 때는 개인차 한정 문장을 붙인다.

**분량은 원문 대비 65~75%를 목표로 하되 맞추려고 지어내지 않는다.** 스핀·마케팅 비중이 큰 원문은 실질을 다 담아도 50% 아래에 머문다(라미네이트 편이 48%). 그때는 사유를 원고 문서에 남긴다. 글자 수가 아니라 **원문 핵심 사실의 커버리지**가 기준이다.
- 기존 매거진과 키워드가 겹치면 **검색의도로 역할을 분리**한다 — 매거진은 지역/시술 선택 기준, 블로그는 병원·원장 관점의 진료 서술. 상호 크로스링크로 묶는다.

### 9-3. 신규 컬렉션 추가 시 (스키마 변경이 있을 때만)

```bash
npx payload migrate:create <name>            # 로컬. 산출 SQL이 additive인지 반드시 눈으로 확인
# → src/migrations/index.ts에 자동 등록됨 (확인)

# 운영 적용 — pooled가 아니라 UNPOOLED로, push는 명시적으로 차단
DATABASE_URL="$(node --env-file=.env.local -p 'process.env.DATABASE_URL_UNPOOLED')" \
PAYLOAD_DB_PUSH=false \
node --env-file=.env.local node_modules/payload/bin.js migrate:status   # 먼저 상태 확인
# ... migrate 로 교체해 실행 후 다시 status
```

> `.env.local`은 값에 `&`가 있어 **셸 `. ./.env.local` 소싱이 깨진다.** 위처럼 `node --env-file=`로 읽을 것.

**순서 고정: 마이그레이트 → 코드 배포 → 시드.** 코드가 먼저 배포되면 `force-dynamic`인 `/blog`가 테이블 부재로 500난다. 마이그레이트만 먼저 도는 것은 무해하다(구 코드는 새 테이블을 모른다). 배포~시드 사이 `/blog`는 빈 상태 UI로 200을 반환한다.

> **운영 DB를 건드리는 모든 임시 스크립트에도 `PAYLOAD_DB_PUSH=false`를 붙인다.** 시드 스크립트만의 규칙이 아니다. 확인용 한 줄짜리 `payload.find()`라도 push가 켜진 채 `getPayload()`를 부르면 Payload가 스키마를 pull·diff하고 `payload_migrations`에 `dev`(batch −1) 마커를 꽂는다 — P3 베이스라인에서 일부러 제거했던 그 행이다(`docs/prod-migration-runbook.md:156`). 2026-08-14 인증제 신청 컬렉션 배포 검증 때 실제로 재발시켜 수동으로 지웠다. 스키마가 이미 일치하면 DDL 변경은 없지만 마커는 남는다.

**시드 후 캐시 재검증은 자동이지만 확인은 눈으로.** 2026-08-14부터 콘텐츠 페이지가
ISR로 캐시된다(그 전엔 전부 `force-dynamic`이라 매 요청이 DB를 때렸다 —
`docs/성능-감사-2026-08.md`). 모든 `seed:*` npm 스크립트 끝에 `npm run revalidate`가
체이닝돼 있으니 정상 경로로 시드하면 즉시 반영된다. 다만 **스크립트를 직접
`node --env-file=...`로 돌렸다면 재검증이 빠진다** — 그때는 `npm run revalidate`를
따로 실행하고, 발행 URL이 실제로 갱신됐는지 확인한다. 빠뜨리면 최대 1시간 동안
옛 화면이 조용히 나간다.

> `npm run revalidate`는 재검증 후 **캐시 워밍**(`npm run warm`)까지 이어서 돈다.
> 재검증은 캐시를 비우기만 하므로, 그대로 두면 각 페이지·이미지의 첫 방문자가
> 렌더와 이미지 변환 비용을 대신 문다. 실측으로 이미지 최적화기 콜드 미스가
> 385~415ms였다(워밍된 뒤엔 88ms). 워밍은 sitemap의 URL을 전부 훑고 그 HTML의
> `/_next/image` 주소를 브라우저와 같은 `Accept` 헤더로 한 번씩 때린다 —
> 헤더가 다르면 사용자가 받는 것과 다른 캐시 키를 데우게 되므로 그렇게 맞췄다.
> 출력의 "콜드였던 것 N건"이 0에 가까우면 이미 데워져 있었다는 뜻이다.

**마지막 단계 — 출처 대장 갱신.** 시드·검증이 끝나면 `docs/content-sources.md`의 해당 표를 현재 상태로 고치고 §4 변경 이력에 한 줄 남긴다. 이게 빠지면 나중에 근거를 추적할 수 없다.

- **중복은 라운드 안이 아니라 사이트 전체로 본다.** 힐하우스 수원 리프팅 12건은 힐하우스 6편과 중복이 0이었지만 디오디 리프팅 2편과 같은 영역이었다. §9-13이 "라운드 안의 중복"을 새로 챙기라고 적었는데, 한 겹 더 넓혀야 한다.
- **지점 재고 소진의 대가가 이번에 나타났다.** 건대점이 0이 되어 선택 폭이 좁아졌다. 칼럼은 190편으로 늘었고(2026-10-23 신규 1건이 마침 이 라운드의 원문) 미사용분은 수원 55 · 강남 36 · 판교 30 · 대구 29 · **건대 0**이다.
- **예온 원문 공급이 끊겼다.** 네이버 블로그가 **2026-08-26 이후 신규 발행이 없다.** 2025-05~10 양산 구간 235건은 지역·의원 정보가 없는 일반 의학 상식(일부 과거시제 AI 문체)이라 쓸 수 없고, **쓸 수 있는 미사용분은 48건**이다. 2~3라운드 뒤에는 주제를 짜내야 한다 — 별건으로 보고해야 할 사안이다.
- **효과 퍼센트 수치를 가장 크게 덜어낸 라운드다.** 힐하우스 원문이 3상 임상시험 결과를 숫자로 싣고 있어(F-VASI75 달성률, 48주 반응률, 전문가 동의율) §9-2대로 전부 뺐다. 대신 **연구 설계 사실**(랜싯 3상 2건, 18개국 138개 기관, 614명, 48주, 연고·자외선 없이 단독, 평균 유병 16년)은 남겼다 — 효과 수치가 아니라 근거의 조건이고, 빠지면 "신약이 좋다"만 남는다. **체표면적 10% 미만**도 연구 포함 기준이라 남겼다.
- **인증 단계 확인을 이어 갔다.** 강남점은 4단계 중 3단계(의료진 자격)만 충족이라 **"메디록 인증"을 쓰지 않았다.** 기존 강남 2편의 `shortAnswer`에는 들어가 있다 — 배지 과대 표기 별건이고, 새 인스턴스를 만들지 않는 쪽으로 처리했다.
- **디오디가 네 라운드 만에 원문 사진을 다시 썼다.** 원문 82장 중 글자·얼굴 없는 공간 사진이 여섯 장 있었다. 기존 3편이 쓴 외관·시술룸·금색 조형물 로비와 겹치지 않게 유리 천장 라운지를 골랐다. **원문 이미지는 매번 다시 본다** — "디오디는 생성 카드"가 규칙이 아니다.
- `next dev`를 `node --env-file=`로 띄우면 **`--env-file= is not allowed in NODE_OPTIONS`로 죽는다**(next가 자식 프로세스에 NODE_OPTIONS를 그대로 넘긴다). `set -a && . ./.env.e2e && set +a` 후 `npx next dev`로 띄운다.

## 10. 대표 이미지(썸네일)

매거진·블로그 카드 / 상세 히어로 / OG 이미지가 모두 문서의 `thumbnail`(Media 관계) 한 장을 쓴다. optional 필드라 비어 있으면 카테고리 색 플레이스홀더로 렌더된다.

### 10-1. 저장소 — Vercel Blob (선행 조건)

Media는 `staticDir: "media"`(로컬 디스크)로 정의돼 있으나, Vercel 런타임은 파일시스템이 읽기 전용이라 **디스크로는 운영 업로드가 저장되지 않는다.** `@payloadcms/storage-vercel-blob`이 이를 대신한다.

- `BLOB_READ_WRITE_TOKEN`이 있으면 Blob, 없으면 로컬 디스크로 **조용히** 폴백한다. 운영에 토큰이 비어 있어도 에러가 나지 않으므로, 배포 후 `/admin`에서 실제 업로드 1건을 반드시 확인할 것.
- `alwaysInsertFields: true`로 둔 이유: 끄면 플러그인이 붙이는 `prefix` 필드가 토큰 유무에 따라 생겼다 사라져, 로컬에서 만든 마이그레이션이 운영 스키마와 어긋난다.
- `sharp`는 `buildConfig({ sharp })`로 넘겨야 `imageSizes`(thumbnail 400×300 / card 768×432 / feature 1280×720)가 생성된다. 빠지면 리사이즈가 조용히 생략된다.

### 10-2. 파이프라인

```bash
npm run thumbnails:collect   # 예온·디오디 사이트 + 네이버 원문 → .thumbnails/candidates/
npm run thumbnails:cards     # 썸네일 없는 매거진 → 브랜드 타이포 카드 .thumbnails/generated/
# ── 여기서 사람이 눈으로 고른다 (아래 선별 규칙) ──
npm run seed:thumbnails -- --dry   # 원본 존재만 점검
npm run seed:thumbnails            # 1280×720 크롭 → Media 업로드 → 문서 연결
```

- 멱등: 같은 파일명(`<slug>.jpg`)의 media가 있으면 재사용한다. 교체하려면 어드민에서 해당 media를 지운다.
- `collect.ts`가 **fetch 대신 curl**을 쓰는 이유: `gd365.ye-on.com`의 인증서 체인을 Node가 검증하지 못한다(`UNABLE_TO_VERIFY_LEAF_SIGNATURE`).
- 네이버 이미지는 **HEAD가 404**다. `GET` + `Referer: https://m.blog.naver.com/` + `?type=w800`으로만 받아진다.

### 10-3. 운영 시드 전 함정 (실제로 다 밟았다)

1. **Blob 스토어는 반드시 Public으로 생성**한다. private으로 만들면 업로드가 `Cannot use public access on a private store`로 거부된다. 어댑터는 public만 지원하며, 사이트 이미지는 어차피 익명 접근이 가능해야 한다.
2. **`media/`를 먼저 비운다.** Blob에 올릴 때도 Payload는 파일명 충돌 검사에 로컬 `staticDir`를 본다. 토큰 없이 돌린 e2e가 남긴 파일이 있으면 이름이 통째로 밀려(`guide-…-2026.jpg` → `guide-…-2027.jpg`) 멱등 조회가 영영 빗나간다. 지금은 스크립트가 사전에 중단시킨다.
3. **Blob 스토어를 프로젝트에 Connect해도 `BLOB_READ_WRITE_TOKEN`은 안 들어온다.** 자동 주입되는 건 `BLOB_STORE_ID`·`BLOB_WEBHOOK_PUBLIC_KEY`뿐이고, 어댑터가 읽는 건 `BLOB_READ_WRITE_TOKEN`이다. 직접 넣어야 한다:
   ```bash
   vercel env ls production --project medirok | grep BLOB_READ   # 없으면
   TOK=$(node --env-file=.env.local -p "process.env.BLOB_READ_WRITE_TOKEN")
   echo "$TOK" | vercel env add BLOB_READ_WRITE_TOKEN production --project medirok
   ```
   값은 **개행을 붙여** 파이프한다. `printf '%s'`/`< file`처럼 개행 없이 넘기면 CLI가 빈 값으로 저장하는데, `vercel env ls`에는 정상 등록된 것처럼 보여 원인 파악이 어렵다. `✓ Added` 출력이 찍혔는지로 확인할 것.
4. **env 추가 후에는 재배포해야 한다.** 기존 배포에는 주입되지 않는다. 반영 전에는 어댑터가 꺼진 채로 `url`이 `/api/media/file/…`(로컬 디스크 경로)로 나가고 그 URL은 운영에서 500이다. **`/api/media`의 `url`이 `https://….blob.vercel-storage.com/…`인지로 판정**한다.

### 10-7. `/blog` 의원 카드 — 로고 중심 브랜드 커버 (2026-08-02)

카드는 **어둡게·흐리게 깔린 배경 사진 위 중앙 흰 플레이트에 대형 로고**다(`HospitalBrandCover`). 배경은 `hospitals.coverImage`, 로고는 `hospitals.logo` — 둘 다 어드민에서 따로 교체할 수 있다.

- **배경을 글 썸네일에서 끌어오지 않는 이유**: 처음엔 `posts[0].thumbnail`을 썼는데 예온 최신 글이 카드뉴스 타이틀(`"인천 라미네이트"` 글자가 박힌 이미지)이라 배경에 텍스트가 깔렸다. 게다가 블로그 3편의 `publishedAt`이 같아 어느 글이 대표가 될지도 불안정했다. **`coverImage`에는 글자 없는 시설 사진만 넣는다.**
- **로고는 짙은 색 + 흰 플레이트**가 요건이다. 어두운 배경에 상표를 그대로 얹으면 안 읽히고, 색을 바꿀 수는 없다. 예온 `logo.svg`는 리프 마크 단독(#7D6E62, 워드마크는 HTML 텍스트라 SVG에 없음), 디오디는 lockup·mark-white가 전부 흰색이라 `logo-mark-dark.png`만 쓸 수 있다.
- 배경은 `object-cover scale-110 blur-[3px]` + `bg-black/55`. `scale-110`이 없으면 블러가 가장자리를 먹어 컨테이너 배경이 비친다.
- 배경은 `cover.cardUrl`(768×432)로 충분하다 — 어차피 블러 처리다.
- SVG 로고는 `sharp(src, { density: 1200 })`로 래스터화한다. 기본값이면 viewBox 크기(163×24) 그대로 떠서 뭉갠다.
- **파일명은 ASCII로 지정한다**(`Entry.filename`). 병원 slug가 한국어라 그대로 쓰면 `/api/media/file/…`가 퍼센트 인코딩을 해석하지 못해 파일이 있어도 404다.

#### 이미지를 교체할 때 — 반드시 새 파일명 + `--refresh`

두 가지를 **함께** 해야 한다.

1. 엔트리의 `filename`을 **새 이름으로 바꾼다.**
2. `npm run seed:thumbnails -- --refresh=<slug>` — 문서가 물고 있던 기존 media를 지우고 새로 올린다.

```ts
src: cand("yeon-site", "06.jpg"),
filename: "yeon-incheon-laminate-clinic.jpg",   // ← 옛 이름 재사용 금지
```

**파일명을 유지하면 교체가 화면에 반영되지 않는다.** URL이 같아 `/_next/image`의 최적화 캐시가 `(url, w, q)`별로 들고 있는 옛 바이트를 계속 서빙한다. 실제로 겪었다 — Blob의 원본과 `w=828`은 새 사진인데 페이지가 쓰는 `w=640`은 옛 이미지 그대로였다. Blob 어댑터의 `cacheControlMaxAge` 기본값이 1년이라 기다려서 풀릴 문제도 아니다.

교체 후에는 **문서의 media id가 바뀌었는지 + 실제 페이지 스크린샷**까지 확인할 것. API만 보면 교체된 것처럼 보인다.

`/blog`에 쓰이는 이미지(글 썸네일·의원 로고·커버)를 교체했으면 `docs/content-sources.md`도 갱신한다.

#### ⚠ 로컬 개발이 운영 Blob을 읽고 쓰던 문제

`next dev`는 `.env.local`을 자동 로드한다. `.env.local`에 `BLOB_READ_WRITE_TOKEN`이 생긴 뒤로는 **e2e DB로 띄운 로컬 서버가 이미지를 운영 Blob에서 읽고 있었다** — 이름이 같은 운영 파일만 200이고 로컬에서 만든 파일은 404라 원인 파악이 오래 걸렸다. 로컬 업로드가 운영 저장소에 올라갈 수도 있었다.

`.env.e2e`에 `BLOB_READ_WRITE_TOKEN=`(빈 값)을 넣어 막았다. 프로세스 env가 dotenv 파일보다 우선하므로 `set -a; . ./.env.e2e`나 `node --env-file=.env.e2e` 어느 쪽이든 로컬 디스크로 고정된다.

## 11. 병원 후기·별점 (2026-10-31 신설)

### 11-1. 원칙

**`hospitals.rating`·`reviewCount`는 메디록 자체 집계(영수증·휴대폰 인증) 전용이다.** 제3자 플랫폼
수치를 넣지 않는다. 이유 셋 — 이 두 값이 각각

1. JSON-LD `aggregateRating`의 입력이다(`src/lib/schema-generator.ts:215`). 남의 사이트 평점을 자사
   집계로 선언하는 꼴이 된다(§11-5).
2. 대시보드 "외부 집계 후기" 지표의 입력이다(`src/app/(frontend)/dashboard/page.tsx:13`). 구글 집계와
   네이버 집계가 한 합계에 섞인다.
3. 병원찾기 정렬 `rating`·`reviews`의 입력이다(`useHospitalFilters.ts:120-127`).

공개 플랫폼 집계는 `certification.stage2Detail`에 **출처와 기준일을 붙여** 적는다. 예:
`"네이버 방문자 리뷰 510개 공개(2026-10 기준) · 메디록 영수증·휴대폰 인증 후기는 수집 전"`.

외부 발췌 본문은 `reviews[]`에만 넣고, 출처는 `reviewerName` 말미의 `"(Google)"`·`"(네이버)"` 표기로
드러낸다(별도 필드를 두지 않는다 — `src/lib/review-source.ts`가 그 표기를 읽어 라벨을 가른다).
**메디록 검증 여부는 `isReceiptVerified`/`isPhoneVerified`가 가른다.** 검증분이 0건이면 섹션 제목이
`방문 후기 발췌 (n)`으로 바뀌고 숫자는 **실제 렌더된 카드 수**가 된다.

**수집 실패·선별 탈락·0건 지점은 `rating: 0`·`reviewCount: 0`·`reviews: []`를 그대로 둔다.**
비어 있는 것이 틀린 숫자보다 낫다. 0이면 상세 페이지가 "후기 수집 상태" 서술로 바뀌고 ★은 그리지 않는다.

### 11-2. 수집 파이프라인

```
npm run reviews:collect            # 네이버 — 지점당 요청 2회, 3초 간격
ONLY=gangnam,suwon npm run reviews:collect
npm run reviews:collect -- --google  # 구글맵 — Playwright 1회 열람
```

산출물 `.reviews/candidates/<지점>-<플랫폼>.json`과 `.reviews/raw/`(둘 다 gitignore).
→ **여기서 사람이 눈으로 고른다**(§11-3) → `scripts/seed-<병원>.ts`의 `reviews[]`에 손으로 옮겨 적는다
→ `npm run seed:<병원>`.

자동 반영을 만들지 않는다. 선별 규칙이 자동 판별 불가라는 것이 이유이고, §10-4가 썸네일에서 세운 원칙과 같다.
지점별 플랫폼 링크는 고객 공식 사이트(`/ko/clinics/<지점>/`)에서 읽으므로 하드코딩하지 않는다.

### 11-3. 선별 규칙 (자동화 불가 — 반드시 눈으로)

- **병원 답글 제외** — 수집기가 블록의 첫 `body`만 읽어 구조적으로 배제한다(코드가 담당).
- 기기·제품 브랜드명 제외 — "올타이트"·"더엘주사"·"리쥬란"·"울쎄라"·"써마지"·"스컬트라"·"리투오" 등.
  §9-9의 브랜드 배제 원칙 그대로다.
- 효과 단정·전후 비교 제외 — "얼굴 작아졌다", "피부 좋아졌다", "속건조 싹 잡혔다".
- 시술 권유 제외 — "추천합니다", "받으세요".
- 가격·이벤트·패키지 할인 언급 제외.
- **타 의료기관 비교·비방 제외** — "다른 병원에서는 오진했는데", "공장형 아님".
- **비유기적 계정 제외** — 작성자명에 마케팅 대행사·체험단 흔적이 있으면 뺀다.
- 개인 식별 정보 제외.
- **지점당 최대 3건** — 인용 범위를 넘기지 않는다.
- `visitedAt` — 네이버 `created`에 **연도가 없다**("10.23.금"). 최신순 상단만 쓰고 경계가 애매하면 쓰지 않는다.
- `rating` — 네이버 발췌는 **0**. `"★".repeat(0)`이 빈 문자열이라 별이 안 그려지고, 그게 사실이다
  (`ReviewsSection`이 "별점 미제공"으로 표시한다). 구글 발췌는 실제 별점.
- `reviewerName` — `"gah**** (네이버)"` / `"홍길동 (Google)"`.

수집기가 위 항목을 `flags`로 표시하지만 **자동 제외가 아니다** — 판정은 문맥을 봐야 한다.
`"원"`만으로 금액을 잡으면 `"원장님"`에 걸린다(실제로 처음에 그렇게 걸렸다).

### 11-4. 플랫폼별 함정 (전부 실제로 밟았다)

- **네이버는 별점을 제공하지 않는다.** 2021년 폐지로 place 레벨 점수 키가 없고 개별 리뷰도 `"rating": null`
  이다. → 네이버에서 평점은 어떤 방법으로도 가져올 수 없다. 리뷰 수와 본문뿐이다.
- **`m.place.naver.com`은 반복 요청을 차단한다** — 8회쯤에서 `과도한 접근 요청`. `map.naver.com/robots.txt`는
  `Disallow: /`다. → 지점당 요청 2회 상한·3초 간격·차단 감지 즉시 전체 중단. **우회하지 않는다.**
- **SSR 페이로드에서 리뷰와 병원 답글이 같은 `"body"` 키를 쓴다.** 창(window) 기준으로 읽으면 섞인다 —
  `"reviewId"` 블록으로 끊어 첫 `body`만 리뷰로 읽어야 한다(처음에 18건 중 16건을 답글로 오판했다).
- **구글맵은 curl·웹검색으로 안 된다**(JS 블록 페이지). Playwright가 필요하다. 고객 공식 사이트에는
  `naver.me` 단축링크만 있고 Google CID는 없었다.
- **저작자는 작성자 개인이다.** 병원도 메디록도 권리자가 아니라 고객 계약(`content-sources.md` §0)으로
  해결되지 않는다. 짧은 발췌 + 출처 표기 + 원문 링크(인용 범위)로만 쓴다.
- **원천 풀이 유기적이지 않을 수 있다.** 판교점 상위 2건이 `디테일러스 마케팅랩` 계정이었다.
- **긍정만 고르면 광고가 된다.** 판교점에 진료 거부 불만 리뷰가 1건 있었다. 선별이 곧 편집이라는 것을
  잊지 말 것 — 그래서 섹션에 "공개 후기 전체 보기" 링크를 같이 둔다.

### 11-5. `aggregateRating` 판단 (2026-10-31)

**제3자 플랫폼 평점을 자사 `MedicalOrganization.aggregateRating`으로 주입하지 않는다.**
`hospital/[slug]/page.tsx`의 `medicalOrgSchema` 호출에서 `rating`/`reviewCount` 전달을 뺐다.

구글 리뷰 스니펫 정책은 두 갈래다.

1. *self-serving 금지* — 리뷰 대상이 리뷰를 통제하는 경우. 메디록은 **타 사업자** 디렉터리라 해당 없다.
2. *"다른 웹사이트의 리뷰·평점을 집계해 쓰지 말 것"* + *"표시하는 리뷰에 근거해야 한다"* — 예온
   `5.0/114`(표시는 3건)가 **정확히 이 둘을 어긋났다.**

얻을 리치 결과는 없고(정책 비준수 마크업) spammy structured markup 수동 조치 위험만 남는다. SEO
대행사가 운영하는 레포에서 감수할 비대칭이 아니다. `medicalOrgSchema`의 옵셔널 시그니처는 그대로 두어
**자체 수집(영수증·휴대폰 인증)이 가동되면 되살린다.** 화면에는 출처를 밝혀 그대로 노출하므로 사람이
보는 정보는 줄지 않는다.

### 11-6. 실행 기록 — 힐하우스 5지점 후기 서술 보강 (2026-10-31)

힐하우스 5지점만 `rating: 0`·`reviewCount: 0`·`reviews: []`라서 생긴 것들을 고쳤다.

| 증상 | 조치 |
|---|---|
| 상세·카드 6곳에서 `★ 0 · 후기 0개`가 노출 (집계 없음인데 낮은 평가로 읽힌다) | `hasRatingAggregate()`(`src/lib/format.ts`) 분기 → 상세는 줄 생략, 카드는 "후기 집계 전" |
| 후기 섹션이 통째로 사라짐 (`reviews.length === 0` early return) | `ReviewsZeroState` — "후기 수집 상태" + 별점 0의 뜻 + 공개 후기 확인 링크 |
| 미검증 구글 발췌가 `VERIFIED REVIEWS / 실방문 후기`로 표시 (같은 페이지 인증 박스는 "수집 진행 중") | `reviewsProvenance()`(`src/lib/review-source.ts`)로 분기 → `EXTERNAL REVIEWS · 출처 표기` / `방문 후기 발췌 (n)` + 출처 문구 |
| 제목 숫자가 `reviewCount`(114)인데 카드는 3장 | 발췌일 때 숫자를 `reviews.length`로 |
| `stage2Detail`이 5지점 전부 같은 한 문장 | 지점별 네이버 공개 집계 기입 — 강남 175 · 건대 510 · 판교 295 · 수원 1,471 · 대구 627 (2026-10-31 확인) |
| 인증 배지가 통과 단계와 무관하게 "메디록 4단계 인증" (§9-9에 두 라운드 미뤄져 있던 별건) | `formatCertificationBadge()` → 예온 `3/4단계`, 힐하우스 `1/4단계` |
| `certifiedAt`이 빈 문자열인데 `" 확인 완료"`가 렌더 | `"확인 일자 미등록"` |

**발췌 본문은 넣지 않았다.** 네이버 방문자 리뷰 49건을 전수 확인했는데 §11-3을 통과하는 건이 지점당
0~1건이고 내용이 "직원이 친절했다" 수준이었다. 사유 전문은 `content-sources.md` §3.
