## 큐레이션 근거

**왜 이 주제인가** — 수원점은 칼럼이 가장 많고(60편) 원장 3명이 같은 주제를 서로 다른 각도로 썼다. 여러 원장 칼럼을 묶는 병원 명의 글의 표본으로 맞다.

**축** — **"색의 문제와 요철의 문제를 먼저 나누고, 순서를 설계한다."** 흉터 유형 → 도구 차이 → 모공 원리 → 시술 순서 → 레이저 후 색소침착의 원리·예방·관리 → 회차.

**기존 메디록 글과의 관계** — `dod-cheongdam-pigment`(디오디)가 색소·모공을 "이름이 같아도 결이 다르다"는 진단 축으로 다뤘다. 이 편은 **흉터 중심의 시술 순서와 레이저 후 색소침착**이 축이라 겹치지 않는다(병원도 다르다).

**의도적으로 뺀 것**
- `skin-texture-pores-fine-wrinkles`(김수정) — 브랜드 조합 소개가 대부분이고 니들링 원리가 다른 편과 겹친다

## 브랜드·제품명 치환 (런북 §9-6)

원문에 장비·제품 브랜드가 가장 많은 묶음이다. 전부 방식으로 바꿨다.
- 고주파 니들링 장비명 → "고주파(RF) 니들링"
- 프락셀 → "프랙셔널 레이저"
- 콜라겐 유도 부스터·재생 부스터 제품명 → "콜라겐 유도 시술", "콜라겐 부스터"
- 바늘 없는 주입 장비·피지선 억제 장비·수분 관리 프로그램 이름 → 본문에서 제외하거나 "피지선을 겨냥하는 시술", "수분·진정 관리"
- TCA·하이드로퀴논·트라넥삼산·레티노이드·나이아신아마이드는 성분 일반명이라 유지

## 작성 시 지킨 규칙

- **원출처가 병원 웹사이트다** — 네이버가 아니다. 화면 문구("의원 공식 웹사이트 기반 재구성", "(웹사이트)")와 JSON-LD `citation[].@type`(Article)은 `src/lib/blog-source.ts`가 URL 호스트로 판정한다.
- **병원 명의** — `authorDoctor` 없음 → JSON-LD `author`는 해당 지점(Organization). 원장의 판단은 인용 블록으로 옮기고 "— ○○○ 원장 · 힐하우스피부과 칼럼"으로 밝혔다. 인용 블록 안 문장은 원문 문장 그대로다.
- **지점 귀속** — 블로그 글은 지점 1곳에 붙는다. 저자 소속이 틀어지지 않도록 **그 지점 원장의 칼럼끼리만** 묶었다.
- **사실은 시드 검증분** — 주소·역·진료시간·전문의 수는 `scripts/seed-healhouse.ts`(지점 페이지 JSON-LD) 기준.
- **원문 수치는 출처를 밝혀 옮겼다** — "원문이 인용한 연구에 따르면" 형태. 최상급·타 기관 대비 우위 주장은 옮기지 않았다.
- **CTA·자기 홍보 문장 제거** — 원문의 "힐하우스는 ~을 원칙으로 합니다" 류는 옮기지 않았다.
